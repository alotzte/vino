# Архитектура

## Схема

```
фото (браузер, телефон)
   | multipart/form-data
   v
api/routes.py         HTTP-слой, про CV не знает
   v
pipeline/search.py    выбор движка, порог, метрики
   |
   |  engine=remote:  pipeline/remote.py -> HTTP -> контейнер cv
   |                  кроп YOLO -> LoRA-SigLIP 2 -> top-20 -> LightGlue
   |
   |  engine=stub:    normalize.py -> embedder.py -> index.py
   v
catalog.py            каталог "Своё Вино" (SQLite)
   v
ScanResponse          карточка, кандидаты, метрики, время
```

## Модули

| Модуль | Отвечает за | Не знает про |
|---|---|---|
| `api/routes.py` | HTTP, проверку загрузки, коды ошибок | CV, SQL |
| `pipeline/search.py` | порядок шагов, порог, метрики | HTTP, схему БД |
| `pipeline/remote.py` | запросы в CV-сервис, ошибки и откат на заглушку | каталог, HTTP |
| `pipeline/normalize.py`, `embedder.py`, `index.py` | путь `engine=stub` | каталог, HTTP |
| `catalog.py` | структуру дампа и доступ к нему | CV, HTTP |
| `cv/app/*` | весь CV: кроп, эмбеддинг, геометрия, индекс | каталог, профиль, формат ответа для оценки |
| `appdb.py`, `auth.py` | БД профиля и определение пользователя по `X-Device-Id` или подписи MAX | CV, каталог |
| `api/sommelier.py`, `achievements.py`, `lessons.py`, `quiz.py`, `points.py`, `related_questions.py` | функции удержания | CV, HTTP |

Каталог (`wines.db`) и профиль (`app.db`) лежат в разных БД. Каталог только читается,
профиль живёт в отдельном docker-volume.

### CV-контейнер

| Модуль | Шаг |
|---|---|
| `crop.py` | нормализация (EXIF, HEIC, альфа, сторона ≤ 2048) и кроп бутылки YOLO |
| `lora.py` | SigLIP 2 so400m с влитым LoRA-адаптером, вектор 1152-d |
| `index.py` | индекс эталонов на GPU, косинус, top-20 |
| `local.py` | DISK + LightGlue + degensac: число инлайеров с каждым кандидатом |
| `pipeline.py` | каскад целиком и итоговый скор |
| `build_index.py` | офлайн-сборка индекса |

Эмбеддинг и геометрическая проверка работают по одному и тому же кропу, поэтому
`engine=remote` не проходит через `embedder`/`index`, а ходит в CV одним запросом.

### Порог "не найдено"

CV только отдаёт скоры. Порог `VINO_CONFIDENCE_THRESHOLD` применяется в `search.py`
к косинусу top-1 и управляет полем `found` и экраном "не найдено".

В `flat=1` порог не применяется. Все вина из набора для оценки есть в каталоге, так что
пустой slug там всегда промах. Поэтому у `SearchResult` два поля: `slug` с порогом и
`top_slug`, лучший кандидат без порога.

## Каскад распознавания

| Шаг | Как сделано |
|---|---|
| Нормализация | поворот по EXIF, альфа на белое, сторона ≤ 2048, HEIC через pillow-heif |
| Кроп | YOLO11m-seg, выбираем по `conf × √area × centrality²`, если бутылки нет - целый кадр |
| Эмбеддинг | SigLIP 2 so400m с LoRA (12 блоков, ранг 8), 1152-d, адаптер влит в веса |
| Индекс | `ref_lora.npy` 2009×1152 на GPU, полный перебор за 0.7 мс |
| Переранжирование | DISK + LightGlue + pydegensac по top-20, `score = cos + 0.5·min(inl, 200)/200` |

Если CV не отвечает, сервис переключается на заглушку (`engine=stub`), чтобы интерфейс,
каталог и профиль продолжали работать. Точность и задержка на фото с полки приведены в
README, в разделе "Результаты".

### Похожие этикетки

В каталоге много серий, где у одинаковой этикетки отличается только год или категория.
LoRA-дообучение на эталонах каталога разводит такие серии лучше, чем исходный SigLIP 2,
а LightGlue по top-20 переставляет кандидатов по мелким деталям. OCR года пробовали:
после LoRA он не менял ни одного ответа и добавлял до 1.5 с, поэтому его нет.

## Функции удержания

Работают поверх результата скана и в распознавание не вмешиваются. Данные пользователя
хранятся в `appdb.py`. Логина нет: `auth.py` берёт `X-Device-Id` из браузера или
проверенную подпись мини-приложения MAX.

| Функция | Модуль | Что делает |
|---|---|---|
| Цифровой сомелье | `api/sommelier.py` | вопросы, гастропары, аналоги из других виноделен |
| Вопросы по теме | `related_questions.py` | подсказки к карточке по полям каталога |
| История и оценки | `appdb.py` | сканы и оценка вина 1-5 |
| Ачивки | `achievements.py` | за регионы, сорта и винодельни, а не за количество |
| Урок и тест дня | `lessons.py`, `quiz.py` | короткий урок, стрик, 5 вопросов |
| Карта и баллы | `regions.py`, `points.py` | чекины на винодельнях, баллы за отзывы |

Все функции пока на правилах, без LLM. Чтобы подключить LLM к сомелье, достаточно
поменять `advise()`.

`new_achievements` в `ScanResponse` необязательное поле, `flat=1` его не возвращает. Сканы
без `X-Device-Id` (как у скрипта оценки) в историю не пишутся.

## Метрики

`ScanResponse` всегда содержит `f1_top1`, `f1_top5` и `elapsed_ms`. В интерфейсе они
скрыты и появляются по тапу на счётчик каталога в шапке.

Несмотря на названия, это не F1 на валидации. `f1_top1` равен косинусу top-1, `f1_top5`
равен среднему итоговому скору top-5 (косинус плюс бонус за инлайеры).

Целевое время ответа 3 с, скрипт оценки обрывает запрос на 10 с. Сейчас p95 591 мс, большую
часть занимает геометрия по top-20.

## Почему не рекомендованный стек

ТЗ предлагает Nuxt, PostgreSQL + pgvector и Strapi. Мы взяли FastAPI и SQLite: CV всё равно
на Python, а 2009 векторов перебираются на GPU за 0.7 мс, векторная БД тут ничего не
ускорит. Переезд на PostgreSQL затронет только `catalog.py` и индекс.

## Данные

- `data/wines-svoe/wines.db` - 2011 позиций: slug, название, винодельня, регион, сорта,
  категория, цвет, температура подачи, крепость, описание, фото.
- `data/wines-svoe/images/` - 2009 эталонных фото `.webp`.
- База открывается только на чтение (`mode=ro&immutable=1`), том смонтирован как `:ro`.

## Деплой

Контейнер слушает 8000 внутри и опубликован на 109, дальше FRP-туннель и HAProxy на
`https://app.nektarum.ru/vino/`. HAProxy срезает префикс `/vino`, поэтому приложение
живёт на `/`, а `VINO_ROOT_PATH` нужен только для ссылок в Swagger. Подробнее в
`docs/DEPLOY.md`.
